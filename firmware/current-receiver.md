# UNO current receipt and replay checks

`backend/uno_transport.py` now supplies the `SnapshotReceiver` used by the UNO
acquisition adapter. It validates incoming environmental frames and optional
[current-quality payloads](current-wire.md) before yielding them to the service.
This increment changes Python receipt handling; MCU firmware and isolation/input
boundaries are unchanged. The environmental sketch still has no current producer.

## Bounded parsing and frame ownership

The application accepts at most **896 ASCII bytes** of snapshot JSON text.
This is a conservative application policy, not a measured serial/router limit.
Length/type checks precede JSON parsing; non-ASCII text, duplicate keys at any
object depth, NaN/infinity, malformed JSON and unknown frame fields fail closed.
Escaped keys are checked after JSON decoding, so differently spelled encodings
cannot create two copies of a decoded key.

The receiver owns `ts` and `source`; an MCU object supplying either is rejected.
The host assigns a UTC receipt timestamp and `source=hardware`. `seq` must be a
uint32 and strictly increase. Observed frame gaps are allowed, but a duplicate,
decrease, reboot or uint32 wrap requires restarting acquisition. Existing
temperature-only frames remain accepted, including the initial empty MCU frame.

An oversized response is rejected whole, never truncated. The limit applies
after `Bridge.call` has returned a string; it does not bound allocations inside
the SDK or prevent a too-large packet from blocking an upstream decoder. A
future combined environmental/current response may exceed this budget. Select
and test an envelope before connecting it; do not silently drop quality fields.

## Receipt deadline, using only one host clock

The adapter brackets each `Bridge.call('hvac_snapshot')` with
`time.monotonic_ns()`. Request starts and receipts must be ordered and
nonnegative, with no overlapping or backward clock observation. These host
times are not ADC sample timestamps and are never labelled sample apertures.

For each available current channel, let `A` be the producer's declared sample
age in microseconds, `M` its policy age limit, `S` the host request start in
nanoseconds, and `R` receipt time. The receiver requires:

```text
deadline = S + (M - A) * 1000
R <= deadline
```

No fractional microsecond is rounded away: a receipt one nanosecond past the
deadline fails. Example **synthetic** policy: `A=1000 us`, `M=5000 us`, `S=0`.
Receipt at 4,000,000 ns passes; at 4,000,001 ns it fails. The numbers are test
fixtures, not a selected production policy or a measured UNO Q response time.

This is conservative only under a necessary integration precondition: **the
producer creates its fresh snapshot during this particular request**, with a
qualified age clock/rate and truthful timing evidence. It must not return
cached current JSON from before the request. Starting the remaining budget at
the earlier host request start charges the whole round trip, including request
delivery, producer work and response delivery. Clock-rate/error margins still
need justification on hardware. The current environment-only cache carries no
numeric currents; a future callback must invoke the fresh writer correctly.

The receiver preserves source `age_us` unchanged. Receipt times/deadlines remain
process-local; it does not pretend to have converted the source clock into the
host clock or persisted a new timestamp-provenance schema.

## Repeated windows cannot renew their lease

Each of the three channels retains only its latest window identity and receipt
state; memory does not grow with the number of requests.

- A lower window ordinal is rejected. A higher one can skip ordinals because
  slow polling can miss many upstream windows.
- The same available ordinal must retain its numeric value, timing evidence and
  calibration references, and its declared source age cannot decrease.
- Its deadline is the earlier of the previous deadline and the new request's
  computed deadline. Repeating a frozen source age therefore cannot keep it
  alive indefinitely.
- An unavailable window revokes that ordinal. A later numeric value using that
  same ordinal is rejected; a genuinely newer valid ordinal can recover.
- Once observed, a channel cannot become unobserved in the same session.

The first nonnull current session pins the stream. A changed/disappeared session
requires a new receiver through an acquisition restart; histories are not
silently spliced. The age policy is fixed within that session. Each channel's
first numeric calibration ID/revision is pinned; changing it also requires a
new session/restart. Startup without current metadata can transition once to a
nonnull current session. Persistent boot identity and calibration approval are
still external requirements, not generated by the receiver.

All state changes are committed only after the entire frame passes. A failure
in channel 2 cannot partially consume channel 0's ordinal or deadline. The
receiver belongs to one acquisition loop and is not a shared concurrent object.

## What happens on failure, and what is still missing

An invalid/expired numeric receipt raises `ValueError`; the existing worker
stops visibly and publishes an acquisition error. It does not replace the
message with a guessed zero, reuse a cached successful frame, or hide the
problem by continuing. A deliberately unavailable upstream current remains
null and can be received without a numeric freshness lease.

These checks run **after a call returns**; they are not a timeout that can cancel
a hung `Bridge.call`. Physical latency, router buffering, SDK cancellation and
reconnect behavior have not been tested. JSONL and Pi adapters do not pass through
this UNO-specific receiver. Their existing validation/spool behavior is unchanged.

Receipt eligibility also is **not permission to display or diagnose from that
value indefinitely**. Engine/SQLite results preserve measurements at ingestion;
later dashboard/status retention still uses the existing whole-frame stale
handling at this boundary. Consumer expiry/error clearing is implemented in the
later live-view layer linked below. The 15-second whole-frame stale flag alone
is not a microsecond current-window lease. The receiver is not a complete
end-to-end freshness guarantee or an authentication system; a dishonest producer
can invent a new ordinal or false evidence.

The later [live-consumer increment](current-live.md) now carries receiver
deadlines into ingestion/status and adds dashboard expiry/failure checks.
Original source records remain historical; no physical clock/transport or
hard real-time browser guarantee has been qualified.

## Pinned transport source review

The local Arduino_RouterBridge 0.4.3 / Arduino_RPClite 0.3.0 sources were reviewed:

- `Arduino_RPClite.h` defines a 1,024-byte MCU decoder buffer.
- `request.h` defines the default request buffer as a quarter of that (256 bytes).
  Its response uses a separate `MsgPack::Packer`.
- `server.h` calls `pack_response_headers`, dispatches the return value into the
  packer and sends it through the decoder's `send_response`.
- `decoder.h` sends the packer's bytes using a blocking loop; that loop assumes
  writes eventually make progress and supplies no application deadline.
- `bridge.h` uses the default request buffer and advertises it through
  `$/setMaxMsgSize` when the router supports that method.

The 256-byte request array must not be misreported as a proved 256-byte response
limit. Conversely, a successful local pack does not prove router response
capacity. The Linux/router side and complete RPC envelope still require review
and a boundary/round-trip test. The 896-byte receiver policy does not settle
either claim. File hashes and tested versions are in
[receiver-build-record.json](receiver-build-record.json); no upstream sources
were edited or vendored.

## Verification and next increment

Synthetic tests exercise exact/oversized text, duplicate/nonfinite JSON,
host-owned fields, frame reset/wrap, host-clock errors, nanosecond receipt
boundaries, immutable/revoked ordinals, per-channel progression, session/policy/
calibration changes and atomic failure. A fake Bridge verifies that the actual
UNO adapter uses the receiver and brackets its request. The 14 native C++ JSON
fixtures also pass the real receiver as independent zero-latency synthetic
streams. None is a hardware capture.

Run `python -m unittest discover -s tests -v`; the native fixture pipeline in
[current-wire.md](current-wire.md) now exercises receipt parsing too. The pinned
UNO Q self-test is compiled unchanged; no board is uploaded or operated.

Next: enforce consumer-use current expiry/error clearing without rewriting stored
historical measurements, then establish persistent session/clock ownership and
the bounded router envelope before wiring a synchronized acquisition worker.
Protected fixtures, an actual board and reference measurements remain necessary
for aperture timing, clock margins, CT calibration and accuracy qualification.
